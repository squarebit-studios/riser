# Riser USD worker

The server-side half of Riser. OpenUSD is a Python/C++ library, so anything that
needs a real stage — resolving the character reference, recomputing guide
positions from their bindings, converting an upload — happens here rather than
in the store's NestJS backend.

The split is narrow on purpose: this service does only what needs OpenUSD.
Identity, document storage and email stay in the store backend, which already
has all three. The worker never authenticates an end user; the backend calls it
with a shared service token.

It is also the **developer API**: a studio integrating Riser documents into
Maya, Houdini, Blender, Unreal or a standalone script talks to this package.
[API.md](API.md) is the reference, including a full specification of the USD
layer format so a third party can write their own reader.

## What it does

- **Reads** a Riser layer with `Usd.Stage.Open`, resolving the character
  reference so guides can be checked against real geometry.
- **Recomputes** every guide and curve point from its surface binding. The
  browser's stored positions are a hint; these values are authoritative.
- **Validates**: missing required guides, bindings that no longer resolve,
  drift from the authored position, points outside the character's bounds.

## The three-line case

```python
from riser_worker import RiserLayer

layer = RiserLayer.open("hero.usda")
for guide in layer.guides():
    print(guide.id, guide.position)
```

`guide.position` is recomputed from the guide's surface binding against real
geometry, not read back out of the file. That distinction is the whole point of
the package; see [API.md](API.md).

## Command line

```bash
riser inspect     hero.usda            # template, character, counts, sources
riser validate    hero.usda --template auto   # exits non-zero on any error
riser resolve     hero.usda --json     # authoritative positions
riser export-json hero.usda -o out.json
```

Or `python -m riser_worker <command>` straight out of a checkout. Human output
goes to stdout and diagnostics to stderr, so `--json` output is safe to pipe
into a parser. Exit codes are documented in [API.md](API.md#exit-codes):
0 ok, 1 validation errors, 2 usage, 3 bad layer, 4 file not found, 5 template.

## Triangulation

Bindings name a triangle index, which the browser got from three.js. This
package reproduces three's triangulation exactly — triangles unchanged, quads
as a fan `(0,1,2),(0,2,3)` — and **refuses** faces with five or more corners,
because three uses ear clipping there and a subtly different clipper is worse
than a loud failure. Uploads are expected to be triangulated on the way in.

## Running

```bash
pip install -e .            # core: usd-core only, plus the `riser` CLI
python -m pytest tests -q

# with the HTTP surface
pip install -e ".[service]"
RISER_WORKER_TOKEN=... uvicorn riser_worker.service:app --port 8080
```

The core is importable and testable without FastAPI, and the CLI is standard
library only. The service tests skip themselves when the extra is absent.

`tests/fixtures/sample-layer.usda` is generated by the TypeScript writer.
Regenerate it from the repo root with:

```bash
npx vitest run src/doc/fixture.test.ts
```
